    ```typescript
    export interface ProposalEntry {
      sessionId: string;
      timestamp: string;       // ISO-8601 string from the ## header
      target: "cerebrum" | "anatomy";
      content: string;          // body text (trimmed)
      raw: string;              // the full entry including ## header + content (for rewrite)
    }
    ```

    **2. `parseProposals(sessionDir: string, sessionId: string): ProposalEntry[]`**
    - Read `<sessionDir>/proposed-learnings.md` using `fs.readFileSync` + utf-8
    - If file missing or ENOENT → return `[]` silently
    - Split by `\n## ` (lines starting with `##` after a newline — entries are delimited by `## ` at line start)
    - For each block, parse the header line: strip the leading `## `, then match pattern `/^(.+?) → (.+)\n\n([\s\S]*)$/`
      - Group 1: timestamp (ISO-8601)
      - Group 2: target (`cerebrum` or `anatomy` — lowercase the match for comparison)
      - Group 3: content (body text, trimmed)
    - If a block doesn't match, write a warning to stderr (`"OpenWolf: unparseable proposal entry in session ${sessionId}, skipping"`) and skip it
    - Return array of `ProposalEntry` objects (may be empty)

    **3. `listProposals(entries: ProposalEntry[]): void`**
    - If `entries` is empty: print "No pending proposals found" and exit
    - Print a formatted table with columns:
      ```
      Session ID       Timestamp                Target     Preview
      ─────────        ─────────                ──────     ───────
      abc1234          2026-06-23T12:00:00.000Z  cerebrum   Add note about prisma schema...
      def5678          2026-06-23T13:00:00.000Z  anatomy    Remove deprecated scanner...
      ```
    - Column widths:
      - Session: fixed `sessionId` from the session directory name (not the full path)
      - Timestamp: shown as-is from the parsed entry
      - Target: left-aligned, 12 chars wide
      - Preview: first 60 chars of `content` (replace newlines with spaces), truncated to 60 with "..." if longer
    - Use `console.table` is NOT acceptable — format manually with `console.log` and padded strings.
      - Use `String.prototype.padEnd()` for alignment
      - Print separator row (─ chars) between header and data

    **4. `learningsCommand(sessionFilter?: string): void` (exported async)**
    - Accept optional `sessionFilter` string
    - Resolve `.wolf/sessions/` directory via `getWolfDir() + "/sessions"`
    - If sessions dir missing → print "No pending proposals found" and return
    - Read directory entries: `fs.readdirSync(sessionsDir, { withFileTypes: true })`
    - Filter to directories only: `dirent.isDirectory()`
    - If `sessionFilter` is provided, filter dirs to only those matching the filter (match directory name)
    - For each session directory:
      - If `proposed-learnings.md` doesn't exist → skip silently
      - Call `parseProposals(sessionDir, dirName)` and collect entries
      - If the dir can't be read (EACCES etc) → print stderr warning `"OpenWolf: cannot read session directory ${dirName}, skipping"` and continue
    - Call `listProposals(allEntries)`

    **Edge cases handled by parseProposals:**
    - Missing file (ENOENT) → `[]`, no stderr warning
    - Corrupted/malformed entry (doesn't match regex) → stderr warning, skip, continue
    - Empty staging file → `[]`
    - Mixed valid + invalid entries → valid entries returned, invalid skipped with warnings

    Extend `src/cli/learnings-cmd.ts` with the merge command and archive logic, and register it in `src/cli/index.ts`.

    **1. `learningsMergeCommand(): Promise<void>` (exported async)**

    **Phase A — Parse and display proposals:**
    - Use the same `parseProposals` logic from Task 1: scan all session directories in `.wolf/sessions/`, parse every `proposed-learnings.md`
    - Collect all entries into a flat array, tracking each entry's `sessionId` for the archive step
    - If no entries found: print "No pending proposals found" and return (exit 0)

    **Phase B — Interactive selection:**
    - Display a numbered list of all proposals (1-indexed):
      ```
      1. [abc1234] 2026-06-23T12:00:00.000Z → cerebrum
         Add note about prisma schema relationships
      2. [def5678] 2026-06-23T13:00:00.000Z → anatomy
         Remove deprecated scanner references
      ```
    - Print blank line, then: "Enter numbers to merge (e.g. 1,3,5 or 1-5), or 'a' for all, or 'q' to cancel:"
    - Accept user input via `readline` (Node built‑in): create interface with `readline.createInterface({ input: process.stdin, output: process.stdout })`
    - Parse the input:
      - `q` or empty → print "Cancelled." and return
      - `a` → select all entries
      - Comma-separated numbers and/or ranges ("1,3,5-7") → parse into set of 0-based indices
      - Invalid input → print "Invalid selection. Cancelled." and return
      - If selection is empty → print "No entries selected. Cancelled." and return
    - Print: "Merge N proposal(s)? [y/N] " and wait for confirmation
      - Anything except `y` or `Y` → print "Cancelled." and return
    - Close the readline interface

    **Phase C — Lock-protected append:**
    - For each selected entry (in order):
      - Build append text: `"\n" + entry.content.trim() + "\n"`
        - Note: do NOT duplicate the `## TIMESTAMP → TARGET` header — append only the content body, since the target file gets user-visible learnings, not metadata headers
      - Resolve target path: `path.join(getWolfDir(), entry.target + ".md")` → e.g. `.wolf/cerebrum.md`
      - Append via `withFileLock`:
        ```typescript
        import { withFileLock } from "../hooks/wolf-lock.js";
        withFileLock(targetPath, () => {
          fs.appendFileSync(targetPath, appendText, "utf-8");
        });
        ```
      - If the lock acquisition fails (falls through to unlocked write after MAX_RETRIES), print a warning to stderr:
        `"OpenWolf: warning — merge to ${entry.target}.md from session ${entry.sessionId} proceeded without exclusive lock\n"`
        and continue (still do the append)
      - If `appendFileSync` throws an error (EACCES, ENOSPC, etc.), catch it, print:
        `"OpenWolf: failed to merge entry from session ${entry.sessionId} to ${entry.target}.md: ${error.message}\n"`
        to stderr, mark this entry as FAILED, and continue with remaining entries
      - Track each entry as SUCCESS or FAILED

    **Phase D — Archive consumed entries:**
    - Group SUCCESS entries by `sessionId`
    - For each session with at least one SUCCESS entry:
      - Staging path: `path.join(getWolfDir(), "sessions", sessionId, "proposed-learnings.md")`
      - Re-read the staging file with `readText` (to get the current state — entries may have been appended since we first parsed)
      - Re-parse it using the same `parseProposals` logic
      - Identify which entries in the current file match the successfully merged entries:
        - Match by timestamp + target + content (exact string comparison). The raw entries may differ if new entries were appended between parse and merge, so match on fields not raw text.
      - Build updated file content: keep only entries that were NOT successfully merged
      - Write back the remaining entries (or delete the file if empty):
        - If remaining entries exist: `fs.writeFileSync(stagingPath, remainingContent, "utf-8")` — reconstruct the file by joining the `raw` fields of remaining entries
        - If no entries remain: `fs.unlinkSync(stagingPath)` to remove the empty staging file (silently ignore ENOENT)
      - Archive path: `path.join(getWolfDir(), "sessions", sessionId, "merged-learnings.md")`
      - Append consumed entries to `merged-learnings.md` using `fs.appendFileSync`:
        - For each SUCCESS entry belonging to this session, write its full raw block (including `## TIMESTAMP → TARGET` header + content) followed by `\n`
      - If any FAILED entries: print summary to stderr: `"OpenWolf: ${failedCount} of ${totalCount} entries could not be merged. See warnings above.\n"`

    **Phase E — Summary:**
    - Print: `"Merged ${successCount} proposal(s) into cerebrum.md/anatomy.md"`
    - If any FAILED entries, also print: `"${failedCount} entry(ies) failed"` to stderr

    **2. Register merge subcommand in `src/cli/index.ts`:**
    Add to the `learnings` command group (after the `list` subcommand):
    ```typescript
    learnings
      .command("merge")
      .description("Interactively merge selected proposals into shared markdown")
      .action(async () => {
        const { learningsMergeCommand } = await import("./learnings-cmd.js");
        await learningsMergeCommand();
      });
    ```

    **3. Edge case handling summary (all covered):**
    - Missing/corrupted session dirs (not a directory, can't read): stderr warning, continue
    - Unparseable entries: stderr warning, skip
    - Empty staging file: skip silently (no entries from that session)
    - Staging file changes between list and merge (concurrent append by a hook): re-read + re-parse handles this
    - Lock acquisition failure after MAX_RETRIES: proceed unlocked with stderr warning
    - writeFileSync failure on target file: catch, mark failed, continue
    - Staging file write failure: catch, print stderr warning, continue (entries won't be archived but the merge already happened — acceptable race)

    **DO NOT:**
    - Create a separate `readProposals.ts` or split helpers into multiple files — everything lives in `learnings-cmd.ts`
    - Write to `cerebrum.md` or `anatomy.md` outside `withFileLock`
    - Modify `proposed-learnings.md` while a hook might be appending — the window between re-read and write-back is short (single sync read + write, no async gaps)
    - Use `console.table` or any third-party table/CLI library — format manually with `padEnd()`
    - Delete the staging directory or any non-staging files
    - Overwrite existing `cerebrum.md`/`anatomy.md` content — only append
    - Leave the readline interface open — always close with `rl.close()`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI tool → filesystem (.wolf/sessions/) | Untrusted session directories (created by concurrently running Claude Code hooks) — malformed or malicious session dirs must not crash the CLI |
| CLI tool → shared markdown (.wolf/cerebrum.md, .wolf/anatomy.md) | Concurrent write access from multiple merge invocations; writes must not corrupt shared files |
| CLI tool → user stdin | Interactive merge accepts freeform user input — must not execute arbitrary commands or crash on malformed input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Spoofing | session directory names | accept | Plugins control their own .wolf/ directory; no privilege boundary |
| T-06-02 | Tampering | proposed-learnings.md (untrusted session data) | mitigate | `parseProposals` wraps `fs.readFileSync` — ENOENT returns `[]`, unparseable entries are skipped with stderr warning. Content is treated as opaque text, never `eval()`d or executed |
| T-06-03 | Tampering | cerebrum.md / anatomy.md concurrent writes | mitigate | `withFileLock` serializes append operations; lock TTL prevents deadlocks; unlocked fallback still does the append with a warning |
| T-06-04 | Information Disclosure | Session ID leakage | accept | Session IDs are git worktree IDs — no secrets |
| T-06-05 | Denial of Service | Malformed readline input | mitigate | `learningsMergeCommand` parses selection input with regex `/^(\d+(?:-\d+)?)(?:,\s*(\d+(?:-\d+)?))*$/` — any non-matching input prints error and returns; no infinite loops |
| T-06-06 | Elevation of Privilege | CLI-as-root writes | accept | CLI runs as the current user; no privilege escalation path |
| T-06-07 | Tampering | Staging file rewrite during concurrent hook append | mitigate (accepted risk) | The window between re-read and write-back is single-tick sync I/O; if a hook appends mid-rewrite, the new entry is lost. Acceptable — the hook re-appends on next write event |
</threat_model>
