<objective>
Enable the `OPENWOLF_METADATA_DIR` environment variable to allow flexible metadata storage location. Currently, metadata paths are hardcoded to `<project-root>/.wolf/` across the hook-side `wolf-paths.ts`, `init.ts`, and `update.ts`. This change allows users to redirect the metadata directory to alternate mount points or network shares without changing the project layout.

Purpose: Support deployment scenarios where `.wolf/` needs to live outside the project root (shared network drives, dedicated volumes, CI/CD environments).
Output: Env var support in hook-side `getWolfDir()`, `init.ts` wolfDir resolution, `update.ts` wolfDir resolution.
</objective>

  ```typescript
  export function getWolfDir(): string {
    const envDir = process.env.OPENWOLF_METADATA_DIR;
    if (envDir && envDir.trim().length > 0) {
      const resolved = path.resolve(envDir.trim());
      // path.resolve makes relative paths absolute from cwd, but we want to
      // reject actual relative input per D-03. Check if the original value
      // was relative (before resolve).
      if (!path.isAbsolute(envDir.trim())) {
        // Reject relative paths — use .wolf/ fallback
        process.stderr.write(
          `OpenWolf: OPENWOLF_METADATA_DIR must be an absolute path, got "${envDir.trim()}". Falling back to .wolf/\n`
        );
      } else {
        return resolved;
      }
    }
    const ctx = detectWorktreeContext();
    return path.join(ctx.mainRepoRoot, ".wolf");
  }
  ```

  - If unset or empty → fall back to existing `.wolf/` behavior
  - `path.resolve()` is called to normalize (remove trailing slashes, resolve `..`) but we validate `path.isAbsolute()` on the RAW env value before resolving
  - The result does NOT need to be cached here — `detectWorktreeContext()` already caches its result, and `getWolfDir()` is called once per hook execution typically
