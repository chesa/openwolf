<objective>
Deliver an automated local development environment setup for new CHESA team members working on the OpenWolf fork.

Purpose: Reduce onboarding friction by providing a single bash script that verifies prerequisites, installs dependencies, builds the project, links the CLI globally, configures the upstream git remote, and warns about existing global openwolf conflicts. The script is wrapped by an `install:dev` package.json script and documented in both README.md (high visibility) and docs/DEVELOPMENT.md (canonical reference).

Output: `scripts/install-dev.sh` (new), updated `package.json`, updated `README.md`, updated `docs/DEVELOPMENT.md`.
</objective>

    1. **Script naming and scope per D-01**: Name it `scripts/install-dev.sh`. The script targets developer onboarding, not end-user installation. Use `#!/bin/bash` and `set -euo pipefail` (CHESA bash convention per ~/.claude/rules/bash.md). Include a copyright header and pragma marks. Add `--help` and `--version` flags. Use `printf` over `echo`.

    2. **Prerequisite checks per D-05** (fail fast with clear messages):
       - Node.js >= 20: parse `node --version`, extract major version, exit 1 if < 20.
       - pnpm installed: `command -v pnpm` check, exit 1 if missing.
       - Git repository: `git rev-parse --git-dir` check, exit 1 if not in a repo.

    3. **Global install conflict handling per D-03** (warn, do NOT auto-unlink):
       - If `command -v openwolf` succeeds, print a warning to stderr explaining the conflict and suggesting `npm uninstall -g openwolf` or `pnpm unlink --global openwolf`. Continue execution after the warning (do not exit).

    4. **Core setup commands**:
       - `pnpm install`
       - `pnpm build`
       - `pnpm link --global`

    5. **Upstream git remote configuration per D-02** (idempotent):
       - URL: `https://github.com/cytostack/openwolf.git`
       - If `upstream` remote already exists and URL matches, skip silently with a message.
       - If `upstream` exists but URL differs, print a warning and leave it as-is.
       - If `upstream` does not exist, run `git remote add upstream <URL>`.

    6. **Progress output**: Print concise step labels before each major action.

    7. Make the script executable with `chmod +x scripts/install-dev.sh`.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scripts/install-dev.sh -> OS / Node ecosystem | Script executes pnpm and git commands that modify the local filesystem and global node_modules linking. |
| scripts/install-dev.sh -> user | User runs the script with their own permissions; no privilege escalation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | scripts/install-dev.sh | mitigate | Script is created in the repo and executed by the developer. No external download. File permissions set to executable only by owner (`chmod +x`). |
| T-01-02 | Tampering | pnpm install (lockfile) | accept | pnpm verifies lockfile integrity automatically. No additional mitigation needed. |
| T-01-03 | Denial of Service | global link conflict (existing openwolf) | mitigate | Per D-03, script warns and continues rather than auto-unlinking, preventing accidental destruction of a working global install. |
| T-01-04 | Information Disclosure | --version flag | accept | Version string is non-sensitive. |
| T-01-05 | Elevation of Privilege | pnpm link --global | accept | Requires user to already have write access to global node_modules directory; no privilege escalation introduced by this script. |
</threat_model>
