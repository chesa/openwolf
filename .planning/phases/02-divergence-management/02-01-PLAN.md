  <action>
Create `scripts/sync-upstream.sh` as a self-contained bash script following CHESA conventions:

1. Header: `#!/bin/bash`, `set -euo pipefail`, BSD license header, copyright, version string "1.0.0".
2. `#pragma mark *** Section Name ***` organization marks for: Constants, Validation, Remote Setup, Divergence Report, Main.
3. `validate_dependencies()` checks `git` is on PATH; if missing, prints multi-platform install instructions and exits 1.
4. `show_help()` prints comprehensive usage including `--branch`, `--verbose`, `--version`, `--help` with examples.
5. `show_version()` prints "sync-upstream.sh 1.0.0".
6. Parse flags with `getopts` or manual loop: `--help`, `--version`, `--branch`, `--verbose`.
7. `ensure_upstream_remote()`:
   - Check `git remote get-url upstream` (exit-code based, no grep).
   - If missing: `git remote add upstream https://github.com/cytostack/openwolf.git`.
   - Print the URL being used (existing or newly added).
8. `fetch_upstream()`:
   - Run `git fetch upstream`.
   - On failure (non-zero exit), print generic error to stderr and exit 1. In `--verbose` mode, print the git stderr output.
9. `report_divergence()`:
   - Default compare branch: `main`. Override via `--branch`.
   - Print header: "=== Fork Divergence Report ===" with local branch name and upstream ref.
   - Compute `AHEAD=$(git rev-list --count "upstream/${BRANCH}..${BRANCH}")`.
   - Compute `BEHIND=$(git rev-list --count "${BRANCH}..upstream/${BRANCH}")`.
   - Print counts and status category (IN SYNC / AHEAD / BEHIND / DIVERGED).
   - For each status, print contextual `git log --oneline` commands the developer can copy-paste.
   - For BEHIND and DIVERGED, suggest (but do not execute) `git merge upstream/${BRANCH}` and `git rebase upstream/${BRANCH}`.
   - If current branch is not `main` or `develop`, print a warning: "You are on branch 'X'. Comparing against upstream/${BRANCH}. Use --branch to specify a different branch."
10. `main()` orchestrates: validate deps → ensure remote → fetch → report.
11. Make executable: `chmod +x scripts/sync-upstream.sh`.

Security note: Never pass user input (branch name from `--branch`) to `eval`. Use `git rev-parse --abbrev-ref` or validate against a known-safe pattern (`^[a-zA-Z0-9._/-]+$`) before using in commands. Print the canonical branch name in the report header so the user sees exactly what is being compared.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer workstation -> upstream remote | `git fetch` over HTTPS to public repo; no auth required. |
| `scripts/sync-upstream.sh` -> local git state | Script reads local refs and prints reports; no write operations on branches. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | Command injection via `--branch` | mitigate | Validate branch name with `^[a-zA-Z0-9._/-]+$` regex; use `git rev-parse --abbrev-ref` to canonicalize; never pass to `eval`. |
| T-02-02 | Information Disclosure | Verbose fetch errors | mitigate | Generic "fetch failed" to stderr by default; detailed git stderr only with `--verbose`. |
| T-02-03 | Error | Accidental push to upstream | accept | Upstream is HTTPS (no SSH key for push) and documented as read-only; script contains no push commands. Risk is social, not technical. |
| T-02-04 | Denial of Service | Stale lock or network hang during fetch | mitigate | `git fetch` timeout is handled by git itself; script exits non-zero on failure. No local state is locked. |
</threat_model>
